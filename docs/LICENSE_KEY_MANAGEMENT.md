# 根密钥管理

## 核心原则

Ed25519 私钥是整个商业授权体系的根。私钥丢失后，无法继续签发与现有客户程序兼容的新授权；私钥泄露后，获得者可以生成可通过验证的授权码。

严禁把私钥、备份、签发记录或真实授权码放入 Git、公开网盘、聊天记录、客户安装包、网页演示或项目资源目录。

## 第一次正式初始化

1. 完成 `docs/LICENSE_PRECHECK.md` 中的预检查和全部自动测试。
2. 在开发者自己的受控电脑上启动 `tools/license-issuer`。
3. 确认不存在需要恢复的旧根密钥。
4. 展开“初始化新的授权体系”，输入 `创建新的授权体系`。
5. 初始化后不要立即售卖，先导出私钥备份并完成恢复演练。

程序不会在找不到私钥时自动生成新密钥。缺失状态只能由明确恢复或明确初始化解除。

## 两份离线备份

至少保留两份独立副本：

- 主工作副本：签发工具应用配置目录中的 `license-private.key`。
- 离线备份：从“密钥管理”导出的 `*.private.key`，保存到加密移动介质或离线加密存储。

建议再准备一份位于不同物理地点的加密备份。不要只把两个文件放在同一块硬盘。

## 恢复演练

1. 使用测试环境或隔离的签发器配置目录。
2. 选择“恢复已有私钥”并导入备份。
3. 比对恢复前后的 `key_id` 和公钥导出结果。
4. 签发一条测试授权，用客户验签测试验证通过。
5. 删除测试签发记录，确认授权码仍可独立验证。

已有根密钥时，后端只允许恢复公钥完全一致的备份；不同根密钥会返回 `KEY_MISMATCH`，不会覆盖当前体系。

## 公钥同步

公钥可以进入客户源码。签发器导出的公钥 JSON 必须只包含：

- `schemaVersion`
- `keyId`
- `algorithm`
- `publicKey`

执行：

```bash
npm run license:sync-public-key -- /安全路径/shangan-public-key.json
```

同步脚本只更新 `src-tauri/src/license/keys.rs` 中的受控公钥区块。任何额外字段、私钥相关字段、Base64 padding、错误算法、错误 Key ID 或非 32 字节公钥都会被拒绝。

## 密钥轮换

`v0.7.0` 不执行正式轮换，但协议已保留 `key_id`。未来轮换时必须让客户同时信任旧公钥和新公钥，在旧版本仍有用户使用期间不得直接删除旧公钥。轮换需要独立设计、迁移测试和发布说明。
